# MCQ PROVENANCE SYSTEM

Every question in the bank — regardless of origin — lives in the same per-topic `mcqs.json` with a mandatory `source` block. Nothing enters without provenance.

## Source types

| type | Meaning | Required fields |
|------|---------|-----------------|
| `ai` | AI-drafted (Groq/Gemini pipeline), then human-validated | `model`, `validated_by`, `validated_on` |
| `self` | Authored by you directly | `author` |
| `external` | Fed by you from another source (book, PDF, test series, coaching material) | `name` (source name), `ref` (page/question number if known) |
| `pyq` | Actual previous year question | `exam`, `year`, `qno` |
| `ca` | Generated from a current affairs item | `ca_item_id`, `date` |

## Question schema

```json
{
  "id": "POL-08-Q042",
  "topic": "POL-08",
  "stem": "With reference to Fundamental Rights, consider the following statements: ...",
  "options": ["...", "...", "...", "..."],
  "answer": 1,
  "explanation": "Statement 1 is correct because... Statement 2 is incorrect because... (every option addressed)",
  "tier": 3,
  "format": "statement-based",
  "exams": ["capf", "cse"],
  "source": {
    "type": "external",
    "name": "<source-name-as-you-provide>",
    "ref": "<page/qno if provided>"
  },
  "status": "validated",
  "added": "2026-07-19",
  "stats": { "attempts": 0, "correct": 0, "discrimination": null }
}
```

`format` values: `single-factual`, `statement-based`, `match-pairs`, `assertion-reason`, `chronology`, `odd-one-out`, `fill-appropriate`.

`status` lifecycle: `draft → validated → live → retired`.

## Ingestion rules for externally-fed MCQs

When you feed MCQs from any other source:

1. **Same list, tagged** — they merge into the topic's `mcqs.json`, never a separate silo. Filtering by source is a query, not a folder.
2. **Auto-tagging pass** — the pipeline assigns `topic`, `tier`, `format`, `exams` (you confirm/correct in the admin queue). Provenance (`source`) is set from what you declare at feed time.
3. **Dedup check** — before insert, near-duplicate detection against existing stems in the same topic (normalised text similarity). Duplicates surface in the admin queue as "possible dupe — keep both / merge / reject."
4. **Explanation enforcement** — if the fed MCQ arrives without an explanation, the AI drafts one and it enters as `draft` until you validate. No question goes `live` without a full explanation.
5. **Rewrite-don't-copy rule for published sources** — for questions from commercial books/test series, the pipeline rewrites the stem and options in fresh wording while preserving the concept tested (facts and concepts aren't protected; their exact expression is). PYQs are the exception: government exam papers are reproduced as-is with `pyq` provenance.
6. **Batch feed format** — you can feed raw text, photos, or structured lists; the pipeline normalises to the schema and queues everything for your validation. Whatever format is easiest for you on a given day.
